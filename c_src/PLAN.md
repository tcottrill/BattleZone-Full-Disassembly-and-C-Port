# Battlezone C port - plan

Goal: a faithful C11 translation of `../disasm/bzone_program_rom.asm` (the image Atari's
source assembles to: MAME set `bzonea`, $5000 chip CRC32 efbc3fa0), proven call by call and
frame by frame against the real ROM running on the shared 6502 core, then made playable.
No 6502 core at runtime. MAME `bzone` ($5000 chip 13de36d5; 149 bytes differ, see
`../disasm/bzone_alt_5000_diff.asm`) is a later, optional build-time alternate.

Template: the Tempest port (`C:\Source2026\Tempest Dissasembly\c_src`: PLAN.md, README.md,
FINDINGS.md) and, behind it, Space Duel (`C:\Source2026\Space Duel Dissasembly\c_src`:
DESIGN.md, CONVENTIONS.md, NOTES_oracle.md). Their rules apply unless this file says otherwise.

## 0. User decisions (2026-09-18)

1. Start the port once the disassembly is complete (it is: `../disasm/STATUS.md`).
2. **Reuse as much existing C as possible.** Measured by diffing Atari's sources:

| piece | finding | reuse |
|---|---|---|
| Mathbox | microcode source and all 7 PROMs byte-identical to Tempest's | Tempest `mathbox.c/.h`, `mbprom.c/.h` unchanged; addresses $1800 status, $1810/$1818 result, $1860+n write |
| VGUT.MAC | 0 differing lines vs Gravitar's and Red Baron's VGUT.MAC | Gravitar `c_src/vgutil.c/.h` (adapt cell names); Tempest `alvgut.c` is the colour variant, reference only |
| COIN65.MAC | earlier version than Tempest's / Space Duel's (no `$BC` cell; 42 of 587 lines differ) | adapt Tempest `alcoin.c` / Space Duel `coins.c`; lockstep decides |
| BZSOUN.MAC | not shared with any ported game | new translation (~260 source lines) |
| POKEY | one chip at $1820 | `c012294.c/.h` verbatim |
| AVG | monochrome Battlezone AVG (no colour, clip window bits) | `avg.c/.h` from Tempest/Space Duel, adapted; semantics from `../disasm/avg.py` |
| platform | GL beam renderer, XAudio2, raw input, joystick, ini, headless | Tempest/Space Duel `platform/`, `samples.c`, `app_loop.c` pattern |
| harness | oracle + lockstep on `C:\Source2026\shared\ref6502` (never a new 6502 core) | Tempest `tests/refrun.c`, `tests/lockstep.c`, `tools/gen_state.py`, `tools/gen_roms.py` adapted |

3. **Authentic MAME AVG timing, as the Tempest port has it** (user, 2026-09-18). `avg.c` counts the
   AVG's own cycles for every list: state-PROM ticks per opcode (VCTR 8, SVEC 6, STAT/SCAL 7,
   CNTR 5, JSRL 5, RTSL 4, JMPL 3, HALT 2, +1 idle tick after GO; one tick = 8 master cycles of
   12.096 MHz = one 6502 cycle) plus each vector's beam time from the normalizer / SCAL shift
   register (MAME `avgdvg.cpp`). The state PROM is the same chip as Tempest's (036408-01 =
   136002-125, CRC32 5903AF03). `tools\avg_prom_sim.py` (MAME's state machine on the real PROM)
   must agree to the cycle (Gate T). In Battlezone the timing is visible to the program: lists
   end in HALT, the 6502 polls HALT (IN0 bit 6) and the NMI restarts the AVG / swaps the double
   buffer every 6 ticks only if the list has finished - so the oracle, lockstep and the playable
   build all take "AVG busy until GO + cycles/8 CPU cycles" from that one model.
4. File names follow the original modules: `vgut.c`, `coin65.c`, `bzsoun.c`, `bzone_*.c`
   (BZONE.MAC is ~4900 lines: split by its own `.SBTTL` groups), `bzstst.c`.

## 1. Architecture (mirrors Tempest)

| layer | Battlezone |
|---|---|
| state | `machine_state g`: `ram[0x400]` ($0000-$03FF), `vram[0x1000]` ($2000-$2FFF). `cpu_rd/cpu_wr` for computed addresses |
| named cells | `state_defs.h` generated by `tools/gen_state.py` from `../disasm/bzone_defines.asm`: `A_NAME`, `NAME` lvalue, `K_NAME` constants |
| code | one C function per Atari label, lowercased, `/* LABEL ($ADDR) */` on each, `Lxxxx` comments per statement; A/X/Y/C inputs are parameters, documented outputs are return values; every RAM store reproduced, scratch cells included; HLL65 IFxx/BEGIN (BZSOUN) become control flow |
| ROM tables | `progrom.c` ($5000-$7FFF) and `vecrom.c` ($3000-$3FFF) from `tools/gen_roms.py`; never hand-transcribed |
| hardware seam | `hw.h`: IN0 ($0800: coins, slam, self test, diag step, VG HALT b6, 3 kHz b7), OPTION $0A00, OPTON2 $0C00, EMCNT $1000, GOADD $1200, WTCHDG $1400, VSTOP $1600, Mathbox, POKEY $1820-$182F (ALLPOT = control sticks/fire/start, RANDOM), SOUND latch $1840 |
| display | VGUT/BZONE write real AVG words into `g.vram` through `VGLIST`; double-buffered list, NMI swaps every 6 ticks (VTIMER) |
| chips | `c012294.c`, `mathbox.c` (real microcode), discrete sounds = samples driven by the $1840 latch |
| build | `build_all.bat` (VS2022 `cl /W4 /std:c11`): `tests\refrun.exe`, `tests\lockstep.exe`; `build_win.bat` at the playable milestone |

Facts the port depends on (all in `../disasm/*.md`, verified against the listing):
- NMI every 6144 CPU cycles at 1.512 MHz = 246.09 Hz, only while IN0 bit 4 is set (not self test);
  `$INTCT` low nibble 0 -> `SYNC`++ (one game frame per 16 NMIs = 65 ms); VTIMER = 6 NMIs.
- **Security traps**: TRAP1/TRAP2 checksum $36 (54) bytes at offsets $02-$37 of the attract-mode
  vector buffer; TRAP1 is subtracted from the credits at START ($564D) - so the display list
  must be byte-exact. Real AVG words in a modelled vector RAM give this for free.
- Computed jumps by push/RTS: DTAB ($5C84, DRAW), MTAB (MOTION), TTAB ($68BE, TRACK),
  LNGTBL ($6C90, MSGS) -> `switch`. VGUT fall-through chains. Decimal mode at the HITS adds.
- SNDON is called from the NMI and the mainline; ROBCHK likewise; SNDON peeks `$0103,X` on the stack.
- Tank/robot twin cells are indexed X=0/2 across neighbouring names (COLFLG/SAVE1, FIRECT/DQUE,
  TANGLE/NTHETA, OBJCOL/EIRNGE, SNDWRD/SAVE2+1, SHELLX.., LANGLE): the generated lvalues must
  allow `cell[x]` addressing on the flat RAM array.
- No EAROM: high scores are volatile RAM ($0300).

## 3. Verification (as Tempest)

- **Oracle** `tests\refrun.exe`: the real ROM on `shared\ref6502` with the hardware model above; dumps
  `tests\ref\frame_NNNN.ram/.vram` at each pass through MAIN, deterministic; `--mbtest` runs
  MBDIAG.MAC's own table against `mathbox.c`; input scripts (`tests\scenarios\*.txt`) for coin,
  start, sticks, fire.
- **Lockstep** `tests\lockstep.exe`: at every entry into a translated routine, snapshot, run the C
  function with the ROM's I/O replayed, compare all RAM, vector RAM, the I/O sequence and the
  documented return flags. Untranslated callees run as ROM thunks. A mutation test proves it bites.
- **Gates**: V (`avg.c` draws what `../disasm/bzone_shapes.html` draws), 1/N (first and 600 attract
  passes byte-identical with C modules alone), P (scripted coined game incl. a TRAP1 credit check
  and a super-bonus check), S (self test).
